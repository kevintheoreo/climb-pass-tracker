# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project status

Climb Pass Tracker is a phone-first PWA for climbers to track gym passes, starting with Singapore gyms. **The whole app is one main screen: a list of rows, one per pass**, with the columns `Gym | Type | Expiry | Left`. The Left column has `−` / `+` buttons. The same gym can appear in many rows (two multipasses at one gym are two rows). There is no Gyms screen, no History screen (only a History section below Finished) and no bottom tab bar; Settings is reached from a gear icon. The first column is a text box with gym autocomplete, and a typed name that matches no gym is saved as a new gym.

`docs/PRD.md` (v2.4: single screen, local-only, backup file) is the source of truth for scope and behaviour; `docs/IMPLEMENTATION_PLAN.md` is the step-by-step build plan (milestones M1–M3). Read both before implementing anything, and cite decision IDs (D1–D59) and requirement IDs (FR-1…FR-78) when relevant. IDs are stable across versions; superseded ones are marked in the PRD, so do not follow a D/FR that the PRD marks Superseded or Removed.

Progress: steps 1.1 to 1.11 are merged (milestone 1, the on-device app, is built): setup, domain logic, local database, app shell, the rework for the single-screen model, the list of rows, the `−` / `+` counter (`Counter.tsx`, rules in `counterView` in `src/domain/counter.ts`), the blank add-a-pass row (`NewRow.tsx`, `GymCombobox.tsx`), and editing and deleting (`EditPanel.tsx`; both forms share `PassForm.tsx` and the checks in `src/domain/passForm.ts`), reminder banners (`ReminderBanners.tsx`, one per pass), Settings (reminder thresholds and switches, backup file, delete all data, install steps, version), and the end-to-end tests (`e2e/journey.spec.ts` follows the flows of PRD section 8 from an empty app, with no data put in behind the app's back). **Milestone 2 is also built, and it is not accounts and sync: the owner dropped the server, so the app is local-only and a person moves to another device with a backup file (Settings: download a backup, open a backup file; D37, D38, FR-62, 64–66), or through their own Dropbox if they connect it (optional, D59).** Step 3.1 (the owner's checked gym list) is done; the rest of milestone 3 is next. Work happens on a feature branch per step, merged into `main` through a PR (CI runs on every PR and on pushes to `main`). Key modules: `passStatus.ts` (`getPassStatus`, entries left, freezes), `cycle.ts` (monthly membership periods and reset dates), `counter.ts` (`canUseEntry`, `planGiveBack`: what `−` and `+` may do), `rows.ts` (`buildRows`: the sorted active list and the Finished split), `gyms.ts` (gym list, `searchGyms`, `resolveGymInput`), `reminders.ts` (`getReminders`: expiring, low, monthly reset; `groupByPass`: one banner per pass), `money.ts` (`parseSgd`, `formatSgd`), `history.ts` (`buildHistory`: every live use, newest first; `checkUseDate`: where a use's date may be moved to, D58, FR-76).
- `src/db/` holds the Dexie schema (`db.ts`, version 3) and `repo.ts`, the only code that reads or writes it (`import { repo } from './db'`). It validates input, sets timestamps and deletes: `repo.deletePass` removes a pass and its uses and freezes for good (D52), while undoing a use (`+`), removing a freeze and removing a user gym only set `deletedAt` (reads return live rows only). `repo.useEntry` (`−`) and `repo.giveBackEntry` (`+`) check the counter rules and write inside one transaction, so a double tap never counts twice; `repo.updateUseDate` changes a recorded use's date after `checkUseDate` (the time of day stays; a refusal writes nothing); `repo.deleteUse` removes one use from the history by flagging it deleted, like `+` (the pass gets the entry back); `repo.findOrCreateGym(typed)` turns the gym cell's text into a gym, creating a private one when nothing matches. Reads are plain async functions so they work inside `useLiveQuery`. `repo.getSettings` never throws: a missing row or a stored field that is no longer valid falls back to its default, because the main screen waits on the settings and a failure there would leave it empty. `ErrorBoundary` (in `main.tsx`) shows what went wrong, with details, if anything below it crashes, instead of a blank page. `repo.exportBackup`, `repo.previewImport` and `repo.importBackup` write and read the backup file; the format and the merge rules (add and merge, never replace; the newer edit wins; same-name gyms are one gym; the import is one transaction and can be repeated safely) are in `src/domain/backup.ts` (`buildBackup`, `parseBackup`, `planImport`), and the UI is `src/features/settings/BackupControls.tsx`. ## Architecture rules that span the codebase

- **Local-only.** Every write goes to IndexedDB. There is no server and no sign-in. All flows work offline. The one outside connection is the optional Dropbox backup, which the person has to connect and which sends only to their own Dropbox (D59).
- **Records:** client-generated UUIDs plus `created_at`, `updated_at`, `deleted_at`. Deleting a pass is a hard delete (D52); undone uses, removed freezes and removed user gyms are flagged so a backup can carry them. Importing a backup merges by id, the newer `updatedAt` wins (a tie keeps the local row), nothing is removed except by a newer deletion of a use or freeze, and a pass a file marks deleted (old files) is ignored.
- **Derived, never stored:** `entries_left = total_entries − initial_used − count(non-deleted uses)` (never below 0; for a monthly membership `monthly_entries − count(uses in the current period)`), a membership's `effective_end_date = expiry_date + sum(freeze lengths)`, and pass status (Active / Expiring soon / Low / Used up / Expired – X unused / Frozen). "Finished" is derived from status, not stored.
- **`−` = one use.** It records a `Use` (a timestamp only, never a person's name or a note; D3, D4, D26). `+` removes the latest recorded use, or lowers `initial_used` when none is recorded. Both run in one transaction. Uses are shown only in the History section (D58).

## Domain rules that are easy to get wrong

- Pass types: multipass and class pack have counters and behave identically; a single entry is a counted pass with exactly 1 entry whose expiry is optional; a membership's Expiry is its end date and freezes push that date back (P1). A membership is either unlimited (the Left column says "Unlimited", no counter) or has an optional **entries per month** allowance: then it has a counter for the current month, shows "resets 15 Nov", stays in the main list at 0 and returns to the full allowance at each reset (unused entries are lost). The reset day defaults to the purchase date's day, is editable (1–31, clamped to the month's last day), and a freeze does not move it (D32, D33, FR-57, FR-58). A pass is usable **through** its expiry date.
- The counter stays between 0 and the total entered when the row was created (D25); for a monthly membership, between 0 and the monthly allowance, counting only uses in the current period. `−` is disabled at 0; used-up and expired rows move to the collapsed **Finished** section, where they can be deleted. Editing an expiry to a later date moves a row back up.
- Rows are not grouped by gym and are sorted newest first by when the pass was added to the app, `createdAt` (D41, which replaced the soonest-expiry order of D31), in the Finished section too. Never pre-select or merge passes by gym.
- The gym text box matches existing gyms ignoring case and punctuation ("boulder+" matches "Boulder+"); an exact match reuses that gym so no duplicate is created; otherwise a new private user gym is saved (D24, FR-53). A typed gym is suggested only while a pass uses it (`repo.listGyms` marks the rest inactive, D56, FR-75); it is never deleted, still names old passes, and typing its exact name reuses it.
- Built-in gyms are tracked **per brand** and carry a **name only**: no pass options, prices or validity periods (D11). Users enter their own price and expiry (with generic +6 / +12 month quick buttons that count from the purchase date).
- A new row saves only when every required cell is valid and **Add pass** or Enter is pressed; leaving the row saves nothing (D49, FR-72). Validation reports every problem at once.
- User-added gyms are private to that user.
- **SGD only**, stored as cents; no currency setting or conversion in v1 (D18).
- Reminders are in-app banners only in v1 (defaults: 14 and 3 days before expiry, ≤ 2 entries left, plus 3 days before a monthly reset when entries are left; each user-configurable and switchable off), and the row a banner is about is highlighted. Monthly memberships never get the "low entries" banner or badge (D34). A banner that the person's own taps on `−` / `+` would bring in is held back until the app is next opened, so the list does not shift under their finger (D42, `ownTaps.ts`). No push notifications.
- No analytics or crash-reporting services (D19). English only.
